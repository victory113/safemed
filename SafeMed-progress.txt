DESIGN AND BEHAVIOR
- Calm blue, white, and pale gray using the existing SafeMed design tokens.
- Simple mobile layout; centered card on desktop.
- Login: email, password, Show/Hide control, validation, registration link.
- Registration: full name, email, password, patient/caregiver choice, login link.
- Readable text, visible labels, autocomplete hints, large controls, focus styles.
- Invalid submissions focus the first field with an error.
- Valid submissions show a truthful demo message; they do not create accounts
  or log anyone in. No credentials are stored or sent to a server.
- Subtle page and button animations with reduced-motion support.
- SafeMed welcome fades in and out in 1.4 seconds, once per tab session.
- The hidden form is inert during the welcome so it cannot receive keyboard focus.
- Reduced-motion users skip the welcome. Storage failures do not prevent access.
- Existing shared UI components and colors were reused without changing them.
- The style guide remains available at /styleguide; unknown routes show a fallback.

CODE WALKTHROUGH (READ IN THIS ORDER)
1. frontend/src/App.tsx
   Wraps the route content in Welcome, which handles the initial introduction.
2. frontend/src/routes.tsx
   Maps / and /login to Login, /register to Register, and /styleguide to StyleGuide.
   Uses ordinary browser links; no router dependency was added.
3. frontend/src/pages/Login.tsx and Register.tsx
   Thin wrappers that select the mode of the shared AuthPage component.
4. frontend/src/pages/AuthPage.tsx
   Holds password visibility, validation errors, and demo submission state.
   FormData reads submitted inputs. validateAuth checks them. Invalid forms focus
   their first error; valid forms show a demo response. Shared Input and Button
   components provide consistent labels, styles, and native control behavior.
   Registration alone includes full name and Patient/Caregiver radio options.
5. frontend/src/pages/auth-validation.ts
   Pure validation rules: required name on registration, valid email, required
   password, and an eight-character password minimum on registration only.
   Passwords are not trimmed. Backend validation will still be necessary.
6. frontend/src/pages/auth.css
   Account layouts, existing color tokens, mobile breakpoint, and animations.
7. frontend/src/pages/Welcome.tsx and welcome.css
   Session flag, reduced-motion detection, 1.4-second timer, cleanup, and overlay.
   To replay the introduction, open a fresh tab session or clear the browser's
   sessionStorage key named safemed-welcome-seen, then reload.
8. frontend/tests/auth-validation.test.mjs
   Five tests: empty registration; invalid name/email/short password; valid
   registration; login without signup-only restrictions; missing login password.
9. frontend/index.html
   SafeMed browser title and page description.
